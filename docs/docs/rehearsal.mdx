# Rehearsal

**A rehearsal is moderato practising against a labelled corpus before it
performs on real users.** Every release runs one. This page is the latest
result, generated by `npm run rehearse` and committed with the code — not a
screenshot, not a claim.

## Why this page exists

A version number tells you nothing about whether a moderation library still
catches slurs. Tests tell you the code does what it did yesterday — they cannot
tell you whether `0.92` is the right place to put the line between "refuse this"
and "ask a human", because that is not a question about code. It is a
measurement, and it moves every time the corpus, the vocabulary or the
classifier changes.

Most libraries in this space publish an adjective. This one publishes the
number, the curve, and the full list of cases it gets wrong.

## How a rehearsal works

1. **Load the corpus** — every case in `corpus/*.jsonl`, each with a human
   label of what *should* happen (`allow` / `review` / `block`).
2. **Classify once.** Every case goes through the provider a single time and
   the raw scores are kept.
3. **Replay the policy** at every threshold in a sweep, over those same fixed
   scores.

Step 3 is the point. Holding the classifier output constant and varying only the
policy makes the sweep a controlled experiment — one variable — rather than
fifty different experiments that happen to be plotted together.

## The four numbers

| | what it means | what a bad value costs |
| --- | --- | --- |
| **Precision** | of everything auto-refused, how much deserved it | real posts silently deleted |
| **Recall** | of everything that deserved refusing, how much was caught | abuse published |
| **Exact match** | all three actions match the human label | queue volume drifts |
| **Decided alone** | share resolved with no moderator | moderator hours |

Precision is the one to watch. A false refusal is invisible to you and infuriating
to the person it happened to — they do not file a ticket, they just stop posting.

## Running it yourself

```bash
npm run build
npm run rehearse                    # offline wordlist — no key, CI-safe
OPENAI_API_KEY=sk-… npm run rehearse   # the real classifier
MODERATO_SCREEN_URL=… npm run rehearse # your own endpoint
```

Writes `docs/static/rehearsal/latest.json` and appends to `history.jsonl`.

## Adding your own cases

The corpus is a plain JSONL file. Add lines:

```json
{"id":"mine-0001","text":"…","expected":"review","surface":"comment","tags":["spam"],"note":"why this is hard","source":"seed","addedAt":"2026-08-16"}
```

Or use the [playground](./playground.mdx) — label a few verdicts, download the
file, drop it in `corpus/`.

**Your corpus should be yours.** These numbers are measured against cases that
reflect one idea of acceptable. Fork the corpus, replace it with text from your
own product, and re-run — that is the only version of this page whose numbers
mean anything about *your* users.

## The rule this page enforces

The rehearsal runs in CI on every commit, and the report is committed alongside
the code. So the metrics on this page cannot describe a version of the library
that no longer exists — if the policy changes and the numbers move, the diff
shows it in the same pull request.

See [Upgrading](./upgrading.md) for the rest of the anti-drift rules.
